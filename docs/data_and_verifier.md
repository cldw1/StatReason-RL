# 数据生成与数值判题代码导读

## 从哪里开始读

运行入口 `scripts/03_prepare_data.py` 调用 `statistics.py:generate_statistics()`，每道题由确定性数学代码计算标准答案，再经过 `quality.py:audit_statistics()` 独立复算，最后由 `storage.py:save_dataset()` 保存 JSONL、数据指纹、文件哈希和 split ID 清单。

公开数据入口是 `gsm8k.py:prepare_gsm8k()`：先解析官方 repository commit，仅下载 `main/train-00000-of-00001.parquet`，再解析唯一 `####` 分隔符，并在完整题目组上划分训练用途。不会下载官方测试 parquet。

奖励入口是 `numeric.py:verify_completion()`。输入必须是实际生成的 completion 和一条题目的标准答案记录。`score_completions()` 支持字符串或一条 assistant 消息，拒绝混有用户提示的完整对话。调用者仍必须正确切除输入 Token；文本解析器无法辨认任意字符串的原始来源。

## 统计数据和模板族

每种题型均覆盖四个正式划分，每个划分使用一个不同数学模板族。SFT 200、RL 400、验证 100、测试 200，共 900 条、28 个模板族。另有 100 条独立标记的 prototype 原型，只用于代码验证，不合并进正式训练。

| 题型 | SFT 模板 | RL 模板 | 验证模板 | 测试模板 |
|---|---|---|---|---|
| 条件概率 | 条件总体计数 | 联合概率和边际概率 | 四格表 | 不放回抽样条件概率 |
| 贝叶斯 | 两来源混合 | 三来源后验 | 赔率与似然比 | 两个条件独立信号 |
| 二项概率 | 恰好 k 次 | 至多 k 次 | 至少 k 次 | 含端点区间 |
| 期望 | 离散 PMF | 有限总体加权均值 | 仿射变换期望 | 联合分布线性函数 |
| 方差 | PMF 总体方差 | 一、二阶矩 | 仿射变换方差 | 指示变量方差 |
| 标准误 | 已知总体方差的均值 | 独立均值之差 | 变换后均值 | 等相关变量均值 |
| 置信区间端点 | 已知σ的双侧下限 | 未知σ的 t 双侧上限 | 两均值差的下限 | 已知σ的单侧上限 |

这是一种模板族外推评测，训练、验证和测试的数学表达形式有分布差异。单个模板族内仍可能高度相关，900 条不能被解释成 900 种独立推理技能。GSM8K 的人工题没有可验证的模板族标签，只保证题目组不跨划分，不声称已证明其语义近重复完全隔离。

## 为什么另写复算函数

`statistics.py` 用 Fraction、组合数和确定性分位数公式构造答案；`quality.py` 用 NumPy 加权均值/中心化方差、SciPy 的 binom.pmf/cdf/sf、norm.interval 和 t.interval 等路径复算。

不同数值路径有助于发现点概率/累计概率、端点包含、方差分母和临界值选错的问题。两条程序路径一致仍不能证明题面没有歧义。因此同时输出 14 条训练样本抽查材料，并保留用户后续人工审查这一环节；未声称做过专家标注。

置信区间明确正态总体、是否已知 σ、n-1 定义的样本标准差、单/双侧及目标端点，并在题面提供足够精度的临界值。标准误的相关样本模板明确不独立，避免误用 σ/sqrt(n)。

## 验证器的六个步骤

1. 标准答案与容差必须有限、容差非负。配置错误抛出异常，不静默转成奖励。
2. 检查 completion 长度和控制字符，统计最终答案标记。NFKC 用于识别伪装重复标记，不能把全角标记自动变成合法输出。
3. 要求唯一 ASCII `FINAL_ANSWER:` 行在输出末尾，且不处于显式 `<think>` 块中。多答案一律拒绝，不选择最后一个或数值正确的那个。
4. `parse_numeric()` 只解析规范整数、小数、科学记数法、千位逗号和一个分数。使用 Decimal 运算，限制长度、位数和指数；不调用 eval。
5. 百分号只在题目显式允许时执行 /100。没有百分号的 25 不会被猜成 0.25；GSM8K 默认不自动转换百分数答案。
6. 比较 `|prediction-answer| ≤ max(absolute_tolerance, relative_tolerance×|answer|)`。严格正确还要求格式有效且没有截断。

概率题绝对/相对容差均为 1e-8，其他统计数值题绝对容差为 1e-6、相对容差为 1e-8。GSM8K 整数要求精确相等，小数使用绝对 1e-9。上述容差基于题目输出精度确定，不根据模型能否答对动态放宽。

`Verification` 同时保留 `structure_valid`、`format_valid`、`parse_success`、`numeric_correct`、`strict_correct`、`truncated` 和原因。单一有效数值答案后附额外内容可记录数值诊断，但格式无效、奖励为 0。思考中的正确数字不会被当成最终答案。

## 截断、损失掩码和超长惩罚

本阶段只实现截断的严格判题规则：`truncated=True` 时严格正确率和奖励均为 0，仍保留解析和格式诊断。该标志将由生成器根据 EOS/Token 实际停止情况提供。

训练时是否掩蔽截断样本损失是单独的配置。DAPO 软长度区间惩罚也是单独的机制，目前未实现。不能把此处的截断判错写成已完成 Overlong Reward Shaping。

## 指纹和重跑

`schema.py:content_fingerprint()` 按题目 ID 排序后，对所有字段的规范 JSON 计算 SHA256。指纹覆盖答案、容差、split 和参数，而不只是题面。

`storage.py` 还保存逐文件 SHA256 和 split_ids。同一数据版本再次构建时校验内容及现有文件，内容变化或文件被修改时拒绝覆盖，需建立新版本。没有模型调用，生成器随机源是每个 split/题型单独派生的 Python Random seed。

当前 freeze 文件记录依赖已安装且 API 导入通过的真实 Windows 环境；这不代表 SFT/GRPO 已经成功训练，也不表示合成统计数据的复算成功率就是模型准确率。
